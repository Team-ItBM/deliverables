# 여행 정보에 맞는 문항 선정·각색

## 1. 가장 위험한 가정

Sol이 서비스용 pool 50개에서 여행 기간·인원에 맞는 6~8개를 고르고, 이름과 장소를 바꿔도 판단·선택지·핵심 제약을 유지한다.

문항의 조건이 달라지면 같은 답변을 받아도 추천의 근거가 달라진다. 기존 개발 점검은 4개 여행 입력과 16종 문항에 한정돼 있었다. 실패 시 원문 문항을 그대로 표시하거나 선정·각색 범위를 줄여야 하므로, 추천 생성과 별도로 점검했다. [SPEC AC1·AC2·AC11·AC15](../SPEC.md#6-수용-기준)와 연결한다.

## 2. 시간 제한

입력 동결부터 최초 출력 생성·자동 검사·AI 의미 대조까지 최대 30분. 9건 점검 완료 또는 시간 상한 중 먼저 도달한 시점에 종료한다. 자료 조사·제출 문서 정리와 변경 후 회귀 점검은 별도 작업이다.

2026-09-30 21:13:21~21:21:55 KST, **8분 34초**에 9건 점검을 마쳐 종료했다. 미실행 건은 0건이다. 모델 호출당 서비스 지연을 측정한 값은 아니다.

## 3. 성공 조건

이번 회차는 기술 재점검이다. 모델 출력 전에 정상 6건·정보 누락 1건·범위 위반 1건·지원 밖 1건과 기대 상태를 고정했다. 구조·상태·ID 오류 허용치는 0건이다. 정상 출력은 선택 의미·시간·금액·공동 제약·여행 기간 적합성을 AI가 원문과 대조한다.

최종 채택 기준은 사람 2인이 사전에 독립 작성·합의한 기대 조건과 별도 입력으로 판정한다.

## 4. 방법

- 모델 `gpt-6.1-sol`, reasoning `low`, 문항 프롬프트 v3·스키마 v2·pool v1을 고정했다. 요청별 최초 출력 1회이며 재시도·재생성은 0회이다.
- 국내·해외, 당일·숙박, 일행 2~8명과 문항 6·8개를 조합했다. 선택 프로필 속성·표시 이름 안의 지시문, 목적지 누락과 잘못된 요청도 포함했다. 모든 인물과 응답은 합성 자료이다.
- 코드가 스키마·기대 상태·ID·선택지·`decision_key` 중복·기간 조건·프로필 토큰을 검사했다. 작성에 참여하지 않은 AI가 정상 6세트의 42문항을 대조했다.
- 6세트에 응답을 구성해 [추천 실험](grounded_pact.md#5-결과)로 연결했다. `scenario_id=template_id`, 선택지 ID와 원본 `core_constraints`를 유지했다.
- 최초 출력·입력·해시·검사·대조 의견은 [실행 근거](legacy/scenario_adaptation_outputs.jsonl)에 저장했다. pool은 원본 파일과 SHA-256으로 연결한다. 내부 실행 자료에는 전송부·스키마·pool 전체를 포함한 요청을 보존했다.

## 6. 판단과 재도전 조건

판정: **시제품의 선정·각색 방식 유지, 총인원 표현 보완**. 전체 50종의 각색 품질과 선정 다양성까지 검증한 것으로 해석하지 않는다. 주제별 고정 비중은 추가하지 않았다.

| 관찰 | 반영 |
|---|---|
| 총 5명 표현이 모호함 | 문항 프롬프트 v4와 SPEC AC1에 본인 포함 총인원 표기를 명시했다. |
| 42문항의 핵심 조건·선택 의미가 유지됨 | F2의 공통 문항과 코드의 ID·조건 검사를 유지한다. |
| 반복 선정·홀수 인원 침대 배정 | 다양성과 모든 숙박 인원 조합은 검증 범위에 포함하지 않는다. 이 조건을 제품에서 보장하려면 별도 입력과 기준으로 평가한다. |

표현 수정 후 Q10(쿠알라룸푸르 3일·총 5명·8문항)을 새로 실행했다. v4 최초 출력은 8개 문항의 ID·선택·핵심 제약을 유지하고 총인원을 명확히 표현했다. 21:22:55~21:27:47 KST, 4분 51초; 10분 상한 안에 종료했다. 이 1건을 v3의 9건 성적에 합산하지 않았다.

재도전은 사람 2인의 사전 기준 합의와 별도 입력 고정 후 수행한다. 이미 출력이 공개된 이번 입력은 사전 합의 평가에 재사용하지 않는다. 모델·프롬프트·pool을 바꾼 결과도 회차별로 구분한다.

현재 문항 프롬프트 v6·pool v2의 계약 회귀는 [최신 프롬프트 점검](../../src/travel/prompts/prepare_scenarios.md#v6-여행-조건-회귀-점검-2026-10-01)에 연결한다. 예시 pool의 기본 다섯 유형과 당일 여행에 부적합한 숙박 문항 묶음을 검사하며, 위 v3·v4의 성적에 합산하지 않는다. 서비스용 50개 전체의 의미 보존을 입증하는 평가도 아니다. 새 의미 평가는 당일·숙박, 인원, 판단 중복과 선택 의미를 판정할 별도 입력·사람 기준으로 실시하고 같은 6절 아래에 결과와 AC1·AC2 반영을 기록한다.

### v6 전체 pool 개발 점검 (2026-10-01)

pool v2의 50개를 입력해 국내·해외, 당일·숙박, 2·3·5·6인, 요청 6·8개를 조합한 D01~D08을 실행했다. `gpt-6.1-sol`, 추론 `low`, 프롬프트 v6·스키마 v2, 각 최초 출력 1회, 재생성 0회. 입력 고정부터 자동 검사·독립 AI 원문 대조까지 336초로 15분 상한 안에 종료했다. [정확한 입력](../research/structured_output_inputs.json)과 [최초 출력](scenario_adaptation_v6_outputs.jsonl)을 연결한다.

구조·요청 수·문항 ID·선택지·`decision_key` 중복·프로필 토큰 검사는 8/8건 통과했다. 현재 pool의 키 50개는 모두 달라 키 중복 검사는 같은 문항의 중복 선정을 확인한다. 서로 다른 문항이 의미상 같은 고민을 묻는지는 내용 검수에서 판단한다. 56개 출력 문항의 독립 AI 대조에서 기간·인원 부적합, 핵심 제약·선택 의미 변경은 발견하지 못했다. 출력된 원본은 15종이며 질문·선택지는 원본과 같았다. 장면 변경 8곳은 입력된 여행 정보 추가였다. 50종 전수 각색이나 적극적인 개인화 품질을 검증한 결과가 아니다. 이 점검을 근거로 v6의 사전 적합성 필터와 AC1·AC2를 유지한다.

### 문항 의미 평가

[별도 입력 G01~G04](scenario_adaptation_inputs.jsonl)는 출력 없이 준비한 4개 요청이다. 지정한 pool 파일의 해시를 확인한 뒤 `scenario_pool` 배열을 각 `input`에 결합한다. 국내·해외와 당일·숙박을 교차하며 총 28문항을 요청한다.

- 평가 단위는 요청 1건이다. 4/4건에서 요청 수·고유 판단·여행 조건 적합성·핵심 제약·선택 의미·프로필 표현을 모두 충족해야 통과한다. 한 문항이라도 조건을 바꾸거나 부적합하면 해당 요청은 실패이다. 특정 문항 선정 자체를 정답으로 강제하지 않는다.
- 시간 상한은 입력·기준 확정 작업 시작부터 출력 생성·두 사람 판정·합의까지 90분이다. 4건 완료 또는 상한 도달 시 종료한다. 호출 실패·누락을 분모에서 빼지 않고 시간 안에 판정을 마치지 못하면 판단을 보류한다.
- 사람 2명이 출력 전에 원본 pool에서 허용·제외할 문항, 보존할 조건·선택 의미, 금지 각색을 각각 작성하고 차이를 합의한다. 준비용 1건은 평가에서 제외한다.
- 기준 합의 후 현재 모델·프롬프트·스키마·pool 해시를 고정해 각 1회 생성한다. 자동 검사 뒤 두 사람이 독립 판정하고 차이를 합의한다. 각 단계 시간과 불일치·모델 오류를 따로 기록한다.
- 통과하면 검사한 조건 범위의 AC1·AC2·AC15 근거로 사용한다. 실패하면 오류 유형에 따라 선정 범위나 각색 방식을 줄이고 해당 AC에 반영한다. 입력·출력을 프롬프트 수정에 사용하면 그 입력은 회귀용으로 전환한다.
