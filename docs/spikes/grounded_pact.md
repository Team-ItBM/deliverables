# 응답 조건을 보존하는 추천 협약서 생성

## 1. 가장 위험한 가정

Sol이 여러 동행자의 선택과 메모를 읽고, 각자의 명시적 요구·한계를 빠뜨리거나 왜곡하지 않으면서 유사한 여행 상황에 사용할 조율 방법을 제안할 수 있다.

응답 조건을 왜곡한 추천은 운영 화면이 완성돼도 서비스의 핵심 목적을 충족하지 못하므로, 방·초대·이미지 저장이 동작한다는 가정보다 이 가정을 먼저 확인해야 한다.

- 실패 영향: 소수의 한계나 같은 선택에 붙은 다른 조건을 놓치면 일방적 양보를 추천에서 반복한다. [로그 1](../research/records/log-01.md)·[로그 9](../research/records/log-09.md)의 표현 어려움과 연결된다.
- 근거 부족: 기본 계약 점검만으로는 서비스용 pool의 여러 문항과 제출 건을 연결했을 때 수정 메모·부분 결과·공동 이동 제약을 보존하는지 알 수 없다.
- 대체 비용: 실패하면 AI가 조항을 완성하는 범위를 줄이고 응답·조건 비교와 사전에 정리한 조율 선택지 중심으로 바꿔야 한다. 문항·대안 관리와 방장의 판단 부담이 늘어난다.

확정한 pool v1의 문항 생성 결과를 추천 입력에 연결해 점검했다. 문항 선정·각색 자체는 [별도 실험](scenario_adaptation.md)으로 구분한다. 방·초대·이미지 저장과 실제 사용자 효과는 이번 실험 범위에 포함하지 않았다.

## 2. 시간 제한

추천 입력 구성·동결부터 최초 출력 생성·자동 검사·AI 의미 대조까지 최대 30분. 12건 점검 완료 또는 시간 상한 중 먼저 도달한 시점에 종료한다.

2026-09-30 21:18:26~21:24:22 KST, **5분 56초**에 12건을 마쳐 종료했다. 미실행 0건이다. 문서 정리와 실제 서비스의 API 비용·응답 지연은 이 측정에 포함하지 않았다.

## 3. 성공 조건

평가 단위는 확정 문항, 채택된 제출 건 ID, 각 제출 건의 선택·메모를 포함한 추천 요청 1건이다. 등록 인원과 채택된 제출 수는 다를 수 있다. 정상 문항 생성 결과와 연결한 6건, 오류·경계 조건을 진단하는 6건으로 구성했다. 연결 6건의 객관식 158개는 모두 각 문항의 첫 선택지였고 메모는 3개였다. R03은 메모가 선택을 수정하지만, 이 구성만으로 다양한 요구 대립의 품질을 대표하지는 않는다.

이번 기술 재점검은 모델 출력 전에 입력과 기대 조건을 고정했으며 구조·상태·ID·근거 누락 허용치는 0건이다. 의미는 아래 항목에 따라 AI가 입력과 대조했다.

| 검사 | 충족 조건 |
|---|---|
| 구조·참조 | JSON·스키마·상태 조합이 유효하고 참조가 같은 상황의 실제 응답·작성자와 연결된다. 조건 변경의 원문 인용도 입력과 일치한다. |
| 응답별 조건 보존 | 선택을 수정한 메모와 명시적 한계를 보존한다. 모호한 응답은 제외 사유로 연결하고 가능한 일부 조항은 반환한다. 제외된 사람에게 행동·비용·대기 의무를 부과하지 않는다. |
| 사실·제안 구분 | 가상 일정·예약을 실제 사실로 바꾸지 않는다. 새 약속은 `proposed_conditions`, 한계 변경은 `required_changes`로 구분하고 수락을 만들지 않는다. |
| 상태·행동 적합성 | 부분 조항·조건부 대안·정보 부족·입력 오류·지원 밖 요청을 구분한다. 재질문하지 않으며 불명확한 응답을 동의자로 포함하지 않는다. |

이번 회차는 구조·참조·응답 조건의 기술 재점검이다. 자동 발급의 최종 채택 기준은 별도 사전 합의 평가의 **80% 이상 통과와 허위 동의·명시적 한계 위반·원문 왜곡 0건**이다. 구조 검사만 충족한 요청은 최종 통과로 세지 않는다. 출력 누락·호출 실패도 전체 요청 수에서 빼지 않는다.

## 4. 방법

1. 문항 출력 전에 6개 여행 입력의 응답 구성 규칙을 정했다. 생성된 문항에 제출 ID·선택·메모를 넣고 `scenario_id=template_id`, 선택지 ID와 원본 `core_constraints`를 유지해 추천 입력을 동결했다.
2. 나머지 6건은 응답 누락·없는 선택지·지원 밖 요청·부분 정보 부족·전체 정보 부족·공동 차량의 상반된 한계로 구성했다. 입력은 합성 자료이며 실제 사용자 응답으로 집계하지 않는다.
3. `gpt-6.1-sol`, 추론 수준 `low`, 추천 프롬프트 v4·스키마 v3으로 요청당 최초 출력 1회씩 생성했다. 재시도·재생성은 0회이다.
4. 코드가 구조·상태·참조와 모든 상황·응답의 결과 연결을 검사했다. 작성에 참여하지 않은 AI가 12건의 220개 입력 응답을 실제 출력과 대조했다. AI 대조는 사람 독립 판정과 구분한다.

입력·최초 출력·요청 해시·자동 검사·AI 대조는 [실행 근거](legacy/grounded_pact_v4_outputs.jsonl)에 케이스 ID로 연결했다.

사람 2명이 모델 출력 전에 각 응답의 바람·명시적 한계·메모 수정·명시한 컨디션/이유/실제 전달 발언과 반드시 보존할 내용을 독립 작성하고 차이를 합의한다. 조항·조건부 대안·제외 중 허용되는 범위를 적되 정답 문장 하나를 강제하지 않는다. 기준을 합의한 뒤 입력과 설정을 고정하고 출력을 생성한다.

건별 통과는 구조·참조, 응답 조건 보존, 사실·제안 구분, 상태 적합성을 모두 충족한 경우다. 명확한 요구를 근거 없이 버리거나 설명만 붙여 전부 제외하면 실패이다. 제외는 해당 입력의 모호함·충돌·검토한 대안과 연결되어야 한다. 일부안을 제시하면서 제외된 사람에게 비용·대기·이동 의무를 부과하면 실패이다. 원래 조건의 변경은 조건부 대안으로 분리하고 수락으로 표시하지 않는다.

공통 판정 규칙은 2026-10-07에 정했다. 사례별 기대 조건은 위 절차대로 두 사람이 독립 작성한다.

1. 선택과 메모가 다르면 메모를 우선한다. 선택지 문구도 메모와 같은 규칙으로 분류한다.
2. 본인이 특정 행동·지출·이동을 하지 않겠다, 할 수 없다, 하고 싶지 않다고 쓰면 금액·시간이 없어도 명시적 한계다. ‘하고 싶다’·‘원한다’와 ‘가능하면’·‘웬만하면’이 붙은 거부는 희망이다. 한계는 작성자 본인의 행동에만 적용하며, 메모에 직접 쓰지 않은 추론은 한계에 넣지 않는다. 근거는 피로로 대안까지 거절한 [로그 1](../research/records/log-01.md#3-사건-흐름), 함께 가서 특정 기구만 타지 않은 [로그 4](../research/records/log-04.md#3-사건-흐름), 아쉬움을 일부만 말한 [로그 9](../research/records/log-09.md#3-사건-흐름)다.
3. 한계 위반이 없어도 명확한 희망을 이유 없이 버리면 실패다. 다른 사람의 한계나 장면 조건과 충돌해 채우지 못한 희망은 그 이유를 밝히면 허용한다.
4. 일부만 참여하는 안은 허용하며 일반 조항의 한 종류로 본다. 함께하길 원한 응답이 있으면 재합류·공동 부분을 넣거나, 그 바람을 이번에 충족하지 못한다고 밝히거나, 조건부 대안으로 제시한다. 그 바람을 언급 없이 지우거나 따로 행동을 모두가 원한 결과처럼 쓰면 실패다. 따로 행동하지 않겠다는 거부는 2번 기준을 따른다. 근거는 별도 행동으로 조율한 [로그 2](../research/records/log-02.md#3-사건-흐름)·[4](../research/records/log-04.md#3-사건-흐름)·[12](../research/records/log-12.md#3-사건-흐름)와 함께하는 시간을 중시한 [로그 9](../research/records/log-09.md#3-사건-흐름)·[10](../research/records/log-10.md#3-사건-흐름)이다.
5. 다른 사람에 대한 추측을 그 사람의 희망이나 동의로 쓰면 바로 실패다.
6. 비용을 빌려주는 안은 빌리는 사람의 지출로 본다. 지출 한계가 있는 사람에게 일반 조항으로 내면 실패이고, 한계 변경을 전제로 한 조건부 대안으로 표시하고 수락으로 쓰지 않으면 허용한다.
7. 허용 결과는 허용되는 것을 모두 적는다. 두 사람의 해석이 합의 후에도 다르면 판단 불가로 남기고 통과로 세지 않으며, 사람 간 불일치에 넣고 모델 오류에는 넣지 않는다.

사례별 허용 결과와 바로 실패하는 결과는 [평가 기록](grounded_pact_eval.jsonl)에 사례 ID별로 둔다. 응답 원문은 [H 입력](grounded_pact_inputs.jsonl)의 같은 ID를 따른다.

출력 후 원본 → `positions` → 추천을 대조한다. 같은 호출의 추출 입장과 조항이 서로 일치해도 원본을 왜곡했으면 실패이다. 출력 후에도 두 사람이 서로의 판정을 보지 않고 건별 통과·실패·근거를 기록한 뒤 차이를 합의한다. 요청 수·생성 수·판정 완료 수, 사람 간 불일치 수와 모델 오류 유형별 건수는 구분해 기록한다. 준비·생성·자동 검사·사람 판정의 실제 시간을 남긴다.

통과하면 이번에 검사한 단일 상황의 요구 보존·조건 분리에 한해 검증 근거로 채택한다. F4 전체 자동 추천의 채택에는 최신 버전의 다문항 연결·전체 정보 부족·미해결 분기와 AC7의 미래 유사 상황 협약 요건도 확인해야 한다. 실패하면 오류가 난 요구 보존·조건 분리 범위를 줄이거나 처리 방식을 바꾸고 해당 AC를 수정한다. 근거가 부족하면 판단을 보류한다. 두 경우 모두 최초 출력·사람 판정·변경한 SPEC 항목을 이 절에 연결한다.

### 기술 점검 현황

2026-10-07에 추천 v11·스키마 v4, Sol(`gpt-6.1-sol`, 추론 `low`)로 P1~P5·E01~E03·R12를 실행하고, 같은 설정으로 한 번 더 실행했다. 회차마다 사례당 1회씩 총 18개 출력을 생성했다. 입력·기대 상태·프롬프트를 바꾸지 않았고, 생성 작업에는 판정 기준이나 이전 출력을 전달하지 않았다. Codex의 격리된 에이전트 실행이며 서비스 API 비용·지연 검증은 아니다. [두 회차의 입력·출력·검사 결과](grounded_pact_v11_regression_outputs.jsonl)를 `run_id`와 사례 ID로 구분해 보존한다. 이 기록의 `prompt_sha256`은 전송부 표시 사이 본문의 해시다.

| 사례 | 두 회차의 상태 | 확인 결과 |
|---|---|---|
| P1 | `proposed` | 구조·참조 통과. 공유 조항의 개인 시간 조건 보존은 추가 확인 필요 |
| P2 | `needs_information` | 제출 내 응답 누락을 구분하고 `positions=[]` 반환 |
| P3 | `proposed` | 모호한 응답의 미확정 사유와 가능한 조항을 구분. 개인 시간 조건 보존은 추가 확인 필요 |
| P4 | `invalid_input` | 없는 선택지를 거부 |
| P5 | `unsupported` | 지원 밖 요청을 구분 |
| E01 | `proposed` | 6개 상황·18개 응답 연결 통과. 이름 표시 검사 실패 |
| E02 | `needs_information` | 응답 18개가 모두 있지만 정보가 부족한 경우를 구분 |
| E03 | `unresolved` | 정보는 충분하나 변경도 허용하지 않는 충돌을 구분 |
| R12 | `conditional_only` | 일반 조항 없이 조건 변경 대안·원문 인용·미확인 동의를 구분 |

두 회차 모두 구조·기대 상태·참조 검사는 9/9건 통과했고, 이름 표시를 포함한 자동 검사는 8/9건 통과했다. E01의 `conditional_alternatives[0].action`과 `[1].action`에서 `{{participant:sub_10}}이`처럼 조사를 고정해 표시 검사가 실패했다. 두 번째 회차에는 `required_changes[].proposed_change`에도 같은 오류가 있다. 원본을 고쳐 통과로 처리하지 않았다.

AI가 입력과 출력을 대조한 결과, 다문항 연결·정보 부족·미해결 분기는 위 구분을 유지했다. 다만 P1·P3의 개인 메모에 있는 ‘1시간’은 `positions`에 남고 공유 조항에서는 ‘필요한 시간’ 등으로 줄었다. 개인이 명시한 시간 조건이 공유 결과에서도 보존되는지는 통과로 확정하지 않았다.

AC7의 미래 유사 상황 협약 요건은 회귀 출력과 기존 H 출력도 대조했다. 회귀의 조항·대안은 상황별 조율 절차로 작성됐으나, H01의 `conditional_alternatives[0].action`에는 ‘이번에는 체험을 미루는’, `required_changes[0].proposed_change`에는 ‘이번 자유 시간에는 체험을 미루고 함께 무료 산책’이 남아 있다. 해당 장면의 해결안에 머물러 AC7을 충족하지 못한다. 이 AI 점검은 기존 사람 평가 10/12의 판정을 변경하거나 그 성적에 합산하지 않는다.

점검은 완료했으며 F4 전체 채택은 보류한다. 이름 조사 오류와 AC7 표현을 보완하고, 개인 시간 조건이 공유 조항에서 사라지지 않는지 확인한 뒤 다시 점검한다. H06·H08의 기존 실패도 후속 개선 대상으로 유지한다.
