# 도원결의 모바일 웹 (`web/`)

Vite + React 18 + TypeScript(strict) SPA다. 서버 계약은 [서버 위임 기록](../docs/prompts/delegation_server.md) §0-A~§0-D와 "편집용 응답"을, 모양은 [DESIGN.md](../DESIGN.md)를 따른다.

## 실행

Node 22가 필요하다.

```sh
npm install
npm run dev        # http://localhost:5173, /api 요청은 VITE_API_BASE(기본 http://localhost:8000)로 넘긴다
npm run dev:mock   # VITE_MOCK=1. 서버 없이 브라우저 안의 가짜 서버로 동작한다
npm run typecheck
npm run test       # vitest, jsdom
npm run build      # dist/
```

## 환경 변수

| 이름 | 뜻 |
|---|---|
| `VITE_API_BASE` | 개발 서버가 `/api`를 넘길 주소. 화면 코드는 늘 같은 출처의 `/api`를 부른다. 배포에서는 같은 출처에서 SPA와 API를 함께 내보낸다고 가정한다 |
| `VITE_MOCK` | `1`이면 `src/mock/`의 가짜 서버를 쓴다. 서비스 워커를 등록하지 않고 푸시 구독도 흉내만 낸다 |

## 모의 모드에서 흉내 내는 것 (`src/mock/`)

- 방 삭제·푸시 상태 조회·해제를 포함한 사용자 API. 상태는 같은 브라우저 탭끼리 나눠 쓰도록 `localStorage`의 `dowon.mock.db`에 둔다.
- 방을 만들고 2초 뒤 문항이 준비된다. 기본은 3개이고, 화면 위 막대의 `새 방 문항`에서 6개나 8개로 바꿀 수 있다(실서비스는 6~8개). 제출 수가 인원에 닿거나 방장이 조기 생성하면 2.5초 뒤 결과가 생긴다.
- 기본 결과는 조항 2개, 조건부 대안 1개, 미해결 조건 1개다. 화면 위 모의 모드 막대에서 다음 생성을 `미해결 결과`나 `생성 실패`로 바꿀 수 있다. 실패 뒤 재시도는 기본 결과로 성공한다.
- 방장 수정(토큰 개수 검사, 메모 15자 인용 검사), 결과 선택, 재생성 한 번 제한, 멱등 키.
- `참여자로 보기`를 켜면 이 탭에서 방장 토큰을 숨긴다.
- 실제 모델·AWS·푸시 발송은 부르지 않는다.

## 화면

| 경로 | 내용 |
|---|---|
| `/` | 랜딩. 주 문구, 예시 협약서(실제 종이), 이 기기의 방 이어가기, 3단계 안내 |
| `/new` | 4단계 방 만들기(`?step=`). 입력은 메모리에만 두고 마지막에 API를 한 번 부른다. 선택 정보를 하나라도 넣으면 "동행에게 알렸어요" 확인이 있어야 보낸다 |
| `/r/:code/created` | 초대 링크 공유, 접힌 방장 링크 |
| `/r/:code` | 이름 고르기, 같은 이름 안내, 등록 정보 안내, 문항 준비 상태, 방장 메뉴. 공개 결과가 있으면 초대 링크로 처음 온 사람은 결과로 간다 |
| `/r/:code/answer` | 한 화면에 한 문항(`?step=`, 브라우저 기록에 남는다), 메모 300자, 제출 전 확인과 공개 안내 |
| `/r/:code/wait` | 진행 상황 폴링(3~5초, 실패하면 20초까지 늘림), 알림 켜기·방별 해제, 협약서 보기 |
| `/r/:code/result` | 협약서 종이, 발급 연출, 이미지 사전 생성, 다운로드·파일 공유·저장 도움말, 서비스 링크 공유. 참여자는 초안 3~5초, 선택본 30초 간격 조회와 화면 복귀 시 즉시 조회, 방별 알림 해제, 방장은 선택본 표시·후보 접기·문구 고치기·방 삭제 |
| `/privacy` | `docs/PRIVACY.md`를 빌드할 때 넣어 그린다 |

방장 링크의 `#host=`는 처음 열 때 `localStorage`(`dowon.host.<room_code>`)에 저장하고 주소창에서 지운다.

발급 연출은 방마다 이 기기에서 한 번만 재생한다(`dowon.seen.<room_code>`). 효과음 설정은 `dowon.sound`에 둔다. 소리는 협약서 보기를 직접 누른 경우에만 난다. 작성 중인 답은 `sessionStorage`에만 둔다.

폰트는 `src/assets/fonts/`에서 직접 제공한다. 출처와 라이선스는 그 폴더의 README에 있고, 다시 만드는 방법은 `scripts/build_fonts.py`에 있다. 공유 문구는 `src/lib/shareText.ts`, 화면별 제목과 noindex는 `src/lib/pageMeta.ts`에 있다.

앱 아이콘과 `og.png`는 `public/`에 있다. 배포 스크립트가 이 파일들에 긴 캐시를 주므로 그림을 바꾸면 파일 이름도 바꾼다.

## 계약에서 정하지 않아 가정한 것

- `GET /api/push/vapid-public-key`의 응답을 `{public_key}`로 가정했다.
- `label`은 결과 단위라 '방장 수정'을 조항 번호 옆이 아니라 종이 머리에 둔다.
- 결과 목록 항목이 AI 원본 문장인지 최신 수정본 문장인지 계약만으로는 분명하지 않다. 방장 화면은 항목에 `editable` 문장(다음 수정이 시작할 판)을 덮어 그리고, 달라진 곳이 있으면 '방장 수정'을 붙인다.
- 실패 항목의 필드 구성이 정해져 있지 않다. `result_id`, `attempt`, `state`, `created_at`만 읽는다.
- 성별·나이대 허용값이 계약에 없다. fixture 값 형태("여성", "20대")를 따른다.
